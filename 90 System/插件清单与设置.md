# 插件清单与设置

推荐组合是 **Tasks + Journals**：Tasks 负责 HOME 待办，Journals 负责日记、周记和日历导航。核心 Templates 按需用于项目等普通笔记的模板插入；也可以由 Agent 直接维护 Markdown。

公开模板不分发 `.obsidian`。个人笔记本保留自己的配置，换机时可以同步或复制，不必每次重配。

## 插件清单

| 插件 | 类型 | 本模板中的定位 |
|---|---|---|
| [Tasks](https://publish.obsidian.md/tasks/) | 第三方 | HOME 必需，汇总并编辑源笔记中的任务 |
| [Journals](https://github.com/srg-kostyrko/obsidian-journal) | 第三方 | 推荐用于日记、周记和日历导航；纯手写或 Agent 管理时可不安装 |
| [Templates](https://obsidian.md/help/plugins/templates) | 核心插件 | 按需启用，手动插入项目等普通笔记模板；Journals 自行应用日记和周记模板 |
| [File recovery](https://obsidian.md/help/plugins/file-recovery) | 核心插件 | 建议启用，用本地快照恢复误改内容；不替代独立备份 |

### Journals 与其他插件的替代关系

采用 Journals 管理本模板的日记和周记后：

- **Periodic Notes：不需要安装。** 周期笔记的创建、命名和模板由 Journals 管理。
- **Calendar：不需要安装。** 日历导航使用 Journals 自带视图。
- **Daily notes（核心）：关闭。** 日记统一从 Journals 创建、打开，避免同一目录有两套设置和入口。
- **Templates（核心）：按需保留。** 用于普通笔记，与 Journals 的周期笔记模板分工不同。

以上是本模板选用 Journals 后的安装方案。Periodic Notes 和 Calendar 本身可以联动；在这里省去它们是因为功能已由 Journals 覆盖。[Journals 官方兼容说明](https://srg-kostyrko.github.io/obsidian-journal/compatibility)

当前笔记和模板没有依赖 Dataview 或 Templater，不需要为了使用本模板额外安装它们。搜索、快速切换和反向链接可使用 Obsidian 自带功能。

## 首次打开：先配置 Tasks

1. 在 Obsidian 中将包含 `HOME.md` 的文件夹打开为仓库。
2. 进入「设置 → 第三方插件 / Community plugins」，允许社区插件，搜索 **Tasks**，安装并启用。
3. 在 Tasks 设置中，将 **Global task filter / 全局任务过滤器** 保持为空，不填 `#task`；模板使用普通 Markdown checkbox。
4. 打开 [[HOME|工作台]]，切换到阅读视图或实时阅览，确认查询区域能显示任务。

HOME 当前包含 `hide toolbar`，该指令从 **Tasks 7.23.0** 才开始支持，因此使用当前 HOME 至少需要该版本。安装时同时满足所选 Tasks 版本对 Obsidian 的要求。版本依据见 [Tasks 布局说明](https://publish.obsidian.md/tasks/Queries/Layout)。

当前模板仍包含明确标注的虚构演示笔记，它们会进入 HOME。正式使用时按 [[README|开始使用]] 移出案例；没有真实待办后，清单为空是正常情况。

## 手动插入模板

在「设置 → 核心插件」启用 **Templates**，设置：

| 设置项 | 值 |
|---|---|
| 模板文件夹 | `90 System/Templates` |
| 日期格式 | `YYYY-MM-DD` |
| 时间格式 | `HH:mm` |

先创建并命名目标笔记，再从命令面板执行 **Templates: Insert template**，选择需要的模板，例如项目笔记使用 `Project`。日记和周记通过 Journals 创建时，由 Journals 应用模板，无需再次插入。由 Agent 创建笔记时，可直接读取对应模板，不依赖核心 Templates。

模板变量和插入方式见 [Templates 官方说明](https://obsidian.md/help/plugins/templates)。

## Journals：统一管理日记和周记

本节是推荐配置，不代表模板已包含插件程序、已启用插件或已完成实机验证。

1. 在社区插件中搜索 **Journals**，确认作者为 **srg-kostyrko**，安装并启用。当前官方文档要求 Obsidian **1.8.7 或更新版本**。
2. 在 Journals 设置中分别创建 `Daily` 和 `Weekly` 两个 journal，周期选择 daily、weekly。
3. 在 Journals 主设置中，将 **Week configuration** 设置为 **ISO 8601**。先确定周规则，再开始创建周记；这里不需要启用影响整个仓库的 **Apply week configuration to all dates in vault**。
4. 按下表设置文件夹、名称和模板。路径均相对于仓库根目录，文件名模板不加 `.md`。

| 设置项 | Daily | Weekly |
|---|---|---|
| Folder | `10 Journal/Daily` | `10 Journal/Weekly` |
| Note name template | `{{date:YYYY-MM-DD}}` | `{{date:YYYY-[W]ww}}` |
| Templates | `90 System/Templates/Daily.md` | `90 System/Templates/Weekly.md` |
| Auto-create today's note | 关闭 | 关闭 |

这里的周记格式采用 Journals 官方写法：小写 `ww` 跟随其 Week configuration；配合 ISO 8601 后，例如 2025-12-29 所在周会命名为 `2026-W01`。不要把其他插件的格式字符串直接当成同一个设置使用。[周规则与跨年示例](https://srg-kostyrko.github.io/obsidian-journal/periods)

配置完成后，通过 Journals 的日历或命令创建、打开日记与周记。在「设置 → 核心插件」关闭 Daily notes；若已有 Periodic Notes 和 Calendar 用于这两个目录，也将它们停用。原有笔记保留，通过下述接入方式关联后再检查日历；无需删除笔记或卸载插件。

Journals 会写入 `journal`、`journal-date` 等属性，修改笔记时保留它们。已有或由 Agent 创建的笔记，可按官方的自动关联、单篇连接或批量加入方式接入；接入前核对目录和命名是否匹配，并检查日历是否显示正确。不要把「演示-」笔记作为真实日记批量导入。[笔记接入说明](https://srg-kostyrko.github.io/obsidian-journal/notes)

现有 Daily 与 Weekly 模板可作为正文模板；日记、周记仍然按需写，不补空白日期，不复制项目待办，不因启用插件就自动生成回顾内容。

### 不使用 Journals 时

可以手动或由 Agent 创建 `10 Journal/Daily/YYYY-MM-DD.md` 和 `10 Journal/Weekly/2026-W39.md` 这样的笔记，分别使用 Daily、Weekly 模板。周记按 ISO 周命名，以周一至周日为一周，跨年时使用 ISO 周所属年份。

如果只需要简单的日记按钮，可以改用核心 Daily notes：目录设为 `10 Journal/Daily`，模板设为 `90 System/Templates/Daily`，日期格式设为 `YYYY-MM-DD`，关闭启动时自动打开。这是未采用 Journals 时的替代方式，不是推荐组合中的额外安装步骤。[Daily notes 官方说明](https://obsidian.md/help/plugins/daily-notes)

## 换机与多设备使用

首次从公开模板建立个人笔记本，需要选择并配置插件。迁移已有个人笔记本时，可以沿用个人配置；`.gitignore` 忽略 `.obsidian` 只影响 Git，不会阻止 Obsidian Sync 同步它。

### 使用 Obsidian Sync

[Obsidian Sync](https://obsidian.md/sync) 是官方付费同步服务。在源设备和新设备连接同一个远程仓库后，分别进入「设置 → Sync → Vault configuration sync」，选择需要同步的设置。

- 同步社区插件时，开启 **Active community plugin list** 和 **Installed community plugin list**。
- 按需开启核心插件及其配置、快捷键等同步选项。
- 等待源设备上传、新设备下载完成，再重启 Obsidian，让插件及设置生效。

同步选项本身不会跨设备同步，需要在每台设备设置。[官方同步设置说明](https://obsidian.md/help/sync/settings)

### 一次性复制个人配置

换机时可复制整个个人仓库，包含隐藏的 `.obsidian` 目录。只复用设置到另一个仓库时，官方支持复制源仓库根目录下的 `.obsidian`，再重启应用。[官方设置迁移说明](https://obsidian.md/help/manage-vaults#Transfer%20settings%20to%20another%20vault)

操作前关闭相关仓库，目标已有配置时先在仓库外备份。打开后检查社区插件是否已启用，以及插件在新设备上是否兼容。个人配置保留在自己的笔记本中，不回传公开模板仓库。

### 电脑与手机使用不同配置

确有需要时，在「设置 → Files and links → Override config folder」指定设备使用的配置目录，例如手机使用 `.obsidian-mobile`，重启后生效。切换名称不会自动复制原设置；可先复制个人 `.obsidian` 为新目录，再做设备专属调整。[官方配置目录说明](https://obsidian.md/help/configuration-folder)

本模板的 Git 忽略规则仅覆盖默认 `.obsidian/`。若个人仓库使用自定义配置目录，也应把实际目录名加入自己的 `.gitignore`。Obsidian Sync 支持多个配置目录，按设备选择所用目录和同步选项即可。[官方设置配置档说明](https://obsidian.md/help/sync/settings#Settings%20profiles)

## 常见问题

| 现象 | 先检查什么 |
|---|---|
| HOME 显示查询代码而非任务 | Tasks 是否已启用；是否处于阅读视图或实时阅览，而非源码模式 |
| HOME 出现查询错误 | Tasks 版本是否支持当前指令，尤其是 `hide toolbar` |
| 任务没有进入 HOME | 是否为未完成 checkbox；全局过滤器是否为空；原文件是否处于 HOME 查询范围；日期对应哪个区域 |
| 日记或周记落在根目录 | 所选创建插件的 Folder 是否已设置；是否从另一插件入口创建 |
| Journals 周数或跨年文件名不一致 | Week configuration 与文件名模板是否按本说明配套设置 |
| 新设备插件或设置没变化 | 配置是否随迁移传输；Sync 的相关选项是否在两端开启；下载完成后是否重启 |
